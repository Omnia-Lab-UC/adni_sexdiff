# Proposal

## Why

The predeclared CN / LMCI / AD arm of `stage-sensitivity` (change `adni-stage-sensitivity`, merged in PR #12) is run pinned and committed. It has rank 6 beside the primary's 8, all three statuses are `same`, and it has its own axis diagnostics. No report quotes it yet. The newest report, `reports/motco-adni-2026-10-29.md`, predates the arm. `REPORT_INPUT_FILES` does not name the arm's files. `STAGE_SENSITIVITY_READING_RULES` binds "every report that quotes the arm", and no report keeps that promise yet. This change extends step 6 so that one report covers the primary, the latent arm, the export variants and the CN / LMCI / AD arm, each beside the primary. It then writes and checks the next report. Like the earlier report changes, it reads committed aggregate files only, so it runs on any clone.

## What Changes

- **Inputs extended**, still committed aggregate files only. Under `results/motco_stage_sensitivity/` the step reads 13 more files:
  - the arm export's `motco_input/manifest.json`;
  - the arm analysis' `result.json`, `analysis_manifest.json` and `summary.md`;
  - the comparison's `stage_sensitivity.csv`, `stage_sensitivity.md` and `stage_sensitivity_manifest.json`;
  - the arm diagnostics' six files.

  That makes 66 inputs in all, 21 of them manifests (17 now). No participant-level file is opened or required. The hashes of the arm's export CSVs, `latent_scores.csv` and `analysis_metadata.csv` are quoted from its manifests. Its `stage_means.csv` and `pls_loadings.csv` are quoted by hash, as the other analyses' are.
- **Gates extended.** All of them run before anything is written, and each names the file or setting, both values and the command to rerun.
  - **Presence.** Every input is present.
  - **Hashes.** Every aggregate file hashes to the value its own manifest records.
  - **Identity.** The arm is `STAGE_SENSITIVITY_ARM`:
    - its export manifest records step `stage-sensitivity` and a `stage_arm` block equal to the constant, and no export variant;
    - its analysis and comparison manifests name the arm;
    - its analysis records no latent adjustment;
    - its diagnostics record `is_primary` false and `stage_arm` equal to `cn_lmci_ad`.
  - **Reported run.** The arm analysis records `n_jobs = REPORTED_N_JOBS` in its manifest and its record. Every `numerics` block is pinned, and all 21 manifests record the same MOTCO, scikit-learn and metabo_adni versions.
  - **Chain.** The chain holds from the cohort manifest and the primary export, through the arm export, analysis and comparison, to the arm's diagnostics: 24 more links, 100 in all. One link is new in kind: the primary feature tables that the arm export manifest names as the source of its floors must match the hashes in the primary export manifest.

  On the committed tree all 24 links hold, and the 9 aggregate files hash to the values their own manifests record. This was checked by a read-only script while this proposal was written.
- **New report section: "Stage-definition sensitivity"**, placed after "Export sensitivity". `REPORT_SECTIONS` grows from eleven to twelve sections. The section holds:
  - **Statistics.** The statistics table, with the primary row and then the arm row, read from `stage_sensitivity.csv`. Each row has a status, and the primary's status is the result. Each analysis' rank, floor, eigengap and null summary are given beside `angle`.
  - **Status sentences.** The status sentences of `stage_sensitivity.md`, generated by the code that writes that file, so the strings are equal.
  - **Latent spaces** of the primary and the arm, side by side.
  - **Arm definition.** The bullets that `stage_sensitivity.md` prints for the arm: its definition, the primary export it takes rows from, with its floors and rows equal to the primary's, the participants kept and dropped, and the run offsets. Beside them, the four tables that file prints, each under a level-3 heading: exported participants by `dx_bl` × sex, sex × stage cells, runs within each stage, and covariate levels (primary and arm).
  - **Run offset** per block, primary and arm, beside the predeclared counts.
  - **Predeclared counts.** The arm export's counts beside `STAGE_SENSITIVITY_EXPECTED_COUNTS["export"]`.
  - **Diagnostics.** The arm's diagnostics, laid out as the other sensitivities' are: flagged rows, components and block PCs. Then each analysis' first component against `phase`.
  - **Reproduction.** The arm analysis' `cli_equivalent`.
- **Other sections extended** from the same inputs:
  - **Summary:** the arm's rank and status lines, and its flagged diagnostic components.
  - **Provenance:** the four manifests, the 13 inputs and the 24 links.
  - **Findings:** every finding and deviation of the four new manifests, copied verbatim.
  - **Reading rules:** a fourth list, `STAGE_SENSITIVITY_READING_RULES`, printed after `EXPORT_VARIANT_READING_RULES` and named beside every table that quotes the arm.
  - **Reproduction:** the `stage-sensitivity` command and the arm's `axis-diagnostics` command.
- **No reading against another sensitivity.** Stage-arm rule 8 reads the arm against the primary only. The report adds no status or sentence that compares the arm with the latent arm or an export variant.
- **Reports of an earlier layout.** No code change is needed: the existing earlier-layout gate covers them.
  - `reports/motco-adni-2026-10-29.md` (eleven sections) becomes a report of an earlier layout. `report --check` on it stops, naming the absent section "Stage-definition sensitivity". It checks at c94f5e7, the commit that added it.
  - `reports/motco-adni-2026-10-28.md` stops the same way and still checks at 36c9cc8.
  - Both stay in place, unchanged.
- **Flags:** `--stage-sensitivity-dir`, the root of `results/motco_stage_sensitivity/`, read through `STAGE_SENSITIVITY_SUBDIRS`. `report` then has eleven flags.
- **Constants:** conventions only.
  - `REPORT_INPUT_FILES` gains the roles `stage-sensitivity/<subdir>`.
  - `REPORT_SECTIONS` gains "Stage-definition sensitivity".
- **Shared sentences keep their bytes.**
  - The report calls `_stage_arm_status_line`, `_stage_arm_definition` and the lead line of `_stage_arm_rules_heading` as they are.
  - The report needs the four arm tables under its own level-3 headings, so the rows of `_stage_arm_lines` move into a helper that both call.
  - A byte gate covers that move. On the committed arm export manifest, the helper's output must equal `main`'s, and it must match the "Arm" block of the committed `stage_sensitivity.md` and of the arm's `summary.md` line by line.
- **Docs.**
  - `README.md`: the `report` section.
  - `AGENTS.md`: the status paragraph (the report now covers the arm), step 6 (66 inputs, 21 manifests, 100 links, twelve sections, eleven flags, the fourth rule list, the second earlier-layout report) and the Layout entries.
  - The `constants.py` and `run_report` docstrings.
  - "Flag and ask" is unchanged.
- **The next report**, `reports/motco-adni-<date>.md`, written on the first date after 2026-10-29 (the user's choice). The 2026-10-29 file is never overwritten, and the date is never back- or forward-dated. It is written on the clean tree from the committed outputs, checked with `--check` and committed alone.

Scientific constants introduced by this change: none. The report decides nothing. It quotes `STAGE_SENSITIVITY_ARM`, `STAGE_SENSITIVITY_READING_RULES` and `STAGE_SENSITIVITY_EXPECTED_COUNTS` with the earlier constants by name, and every number from the records and manifests.

Out of scope, each its own change if wanted:
- Any reading of the CN / LMCI / AD arm against the latent arm or an export variant (stage-arm rule 8), and any crossing of sensitivities.
- The arm's per-statistic reading lines from its `summary.md`. The report prints the status sentences, as it does for the latent arm and the variants.
- A same-day report name such as an ordinal suffix. The user chose to write the report on a later date instead.
- A rewrite of the 2026-10-28 or 2026-10-29 report, or a check of either with the new code.
- Any change to the outputs of `clean`, `cohort`, `export`, `analyze`, `axis-diagnostics` or the three sensitivity steps.
- The remaining registered sensitivities: the other export variants (all 245 NMR columns, the raw scale, `log2(x + 1)`, the generalized log) and the rank sweep.
- Figures, HTML or PDF rendering, and a written discussion.
- The cluster run (constraint 7).

## Capabilities

### New Capabilities
- None.

### Modified Capabilities
- `case-study-report`: these requirements change:
  - the inputs (the arm's files);
  - the chain (through the arm's diagnostics, the floors' source included);
  - the reported-run gate (the arm analysis, 21 manifests);
  - the content contract (the twelfth section);
  - every number pasted (the arm's tables);
  - the interpretive sentences (the arm's status lines, and no reading against another sensitivity);
  - the reading rules carried (a fourth list);
  - the check's report selection (the 2026-10-29 report as an earlier layout);
  - the findings (the arm's carried).

  One requirement is added: the CN / LMCI / AD arm is identified before reporting. `motco-stage-sensitivity` ("Reading rules bind every reader of the arm") already binds every report that quotes the arm. This change fulfils it without changing that text.

## Impact

- `src/adni_sexdiff/constants.py`: `REPORT_INPUT_FILES` and `REPORT_SECTIONS` are extended, and the docstring names the change. No scientific constant is added.
- `src/adni_sexdiff/data.py`:
  - `_report_dirs`, `_report_rerun`, `_REPORT_MANIFESTS` and `_load_report_inputs`: the arm's roles, labels and gates;
  - `render_report`: the new section, and the extended summary, provenance, reading-rules and reproduction sections;
  - the `run_report` signature and docstring.

  `check_report` and the layout gate are unchanged. The output bytes of the stage-sensitivity renderers do not change.
- `src/adni_sexdiff/cli.py`: the `--stage-sensitivity-dir` flag.
- `reports/motco-adni-<date>.md`: added and committed. It is aggregate. The two earlier reports are unchanged.
- `.gitignore`, `scripts/sync_results.sh` and `PARTICIPANT_LEVEL_PATTERNS` are unchanged, since no participant-level output is added.
- No new dependencies. The step takes seconds, makes no MOTCO call and records no numerics.
- Machines: any machine with the Nix shell and the committed tree. No data root, data machine or participant-level file is needed.
- Workflow:
  - Implement and verify, then commit the implementation.
  - On or after 2026-10-30, write the report on the clean tree, check it and commit it alone.
  - Archive, then open the PR and merge.

  Regenerating any input invalidates the report until a new one is written and checked.
