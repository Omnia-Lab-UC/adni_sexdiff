# Proposal

## Why

`clean` is the first step of the pipeline and every later step reads its outputs; today it is a stub, and `CLEAN_OPTIONS`, the only scientific constant it needs, is undecided. The raw-data spike of 2026-10-26 (`spike.md`, counts only) ran metabo_adni 0.5.8's pipeline on the files now in the data root and gave every number this proposal needs to fix the options before any run: the cells after each metabo_adni step, the two platforms' final tables (p180 1592 × 133, NMR 1504 × 245), and the effect each optional transform would have. With the inputs inventoried and the counts predeclared, `clean` can be implemented and run on the workstation now, and the cohort proposal can be written against its manifest.

## What Changes

- **`CLEAN_OPTIONS` decided.** Per platform, metabo_adni's QC with its default cutoffs, its merge, and none of its transforms:
  - `p180`: `mmc 0.2`, `mpc 0.2`, `cv 0.2`, `icc 0.65`, `merge True`; `log2`, `zscore`, `winsorize`, `remove_moutliers`, `residualize_meds` all `False`.
  - `nmr`: `mmc 0.2`, `mpc 0.2`, `merge True`; the same five transforms `False` (`cv` and `icc` are p180-only in metabo_adni and are not set).
  - Fasting file `BIOMARK.csv` (metabo_adni's default); the p180 LOD workbooks read from the working copy.
  The grounds, each from the spike: (a) the paper's participant cutoff of 0.4 and the default 0.2 remove the same participants (0 differ on either platform), so the default stands; the metabolite, CV and ICC cutoffs equal the paper's. (b) metabo_adni's `--merge` is the stacking of the two p180 runs (FIA ⋈ UPLC within run, runs stacked, metabolite intersection) and the metabolite-only NMR table; MOTCO needs exactly one participant × metabolite table per platform, so the merge is done here, by metabo_adni. (c) metabo_adni's `--log2` is `log2(x + 1e-6)`; 35.3 % of p180 values and 53.7 % of NMR values lie below 1, three NMR metabolites hold 41 zeros and the smallest positive value is 4.2e-9, so the pseudo-count is a scale decision with consequences and belongs to `EXPORT_FEATURE_RULE`, stated per platform in the export proposal. `clean` leaves concentrations on the scale the platform delivers. (d) `--zscore` and `--winsorize` would standardize over the 1592 / 1504 cleaned participants rather than the ≈ 1502 of the cohort; scaling is export's and MOTCO's. (e) `--remove-moutliers` would drop 124 of 1502 (p180) and 299 of 1502 (NMR) cohort participants, unevenly across sex × stage (NMR AD: 33 of 125 women, 13 of 158 men); it is not part of the primary pipeline, and a sensitivity arm is its own proposal. (f) `--residualize-meds` in metabo_adni 0.5.8 reads the medication table at `bl`, where 1456 of 1738 rows carry no class, and sees 4 classes with ≥ 20 users instead of the 44 present at `sc`: the flag would silently do almost nothing. Medication is a covariate question for the cohort and analyze proposals, not a cleaning transform; the medication file is not an input of `clean`.
- **`clean` implemented.** Per platform (`--platform {p180,nmr,all}`): the pinned metabo_adni version checked before any file is read; the platform's raw files copied (through the data root's symlinks) into a working copy under `results/cleaned/<platform>.tmp/`, because metabo_adni changes into the directory it reads and writes its outputs there; metabo_adni's functions called in the order of its own `main` (`read_files`, `remove_missing` (metabolites), for p180 `cross_plate_correction`, `remove_cv`, `remove_icc`, `remove_missing` (participants), `consolidate_replicates`, `remove_non_fasters`, `remove_bad_qc_tags`, `imputation`, `merge`) with `CLEAN_OPTIONS`; its printed output, which lists participants, captured to `logs/metabo_adni.log` and never shown; the cleaned table written under the name metabo_adni gives it (`P180.csv`, `NMR.csv`); the directory renamed to `results/cleaned/<platform>/` when complete. AGENTS.md and the `run_clean` docstring call this "the `clean_files` pipeline"; in metabo_adni 0.5.8 `clean_files` is the console script for `__main__.main`, not a library function (there is no library entry point), and both texts are corrected to say so.
- **Run provenance kept.** metabo_adni's merge drops which p180 run (ADNI-1 kit or ADNI-GO/2 kit) a participant was measured on. `clean` writes `p180_runs.csv` (`RID`, `run` ∈ {`ADNI1`, `ADNI2GO`}) from the raw files' participant rows, restricted to the participants of `P180.csv`; a participant present in both runs' files is a finding. It is participant-level and lives in the already-ignored `results/cleaned/`. Whether the run enters the analysis as a covariate is decided by the cohort and analyze proposals, not here.
- **`clean_manifest.json` per platform (aggregate, no `RID`).** metabo_adni and library versions, git revision, the options as applied, a `cli_equivalent` (`clean_files ...`, metabo_adni's console script; `python -m metabo_adni` runs nothing in 0.5.8, whose `__main__.py` has no main guard) that reproduces the run, every input file with its symlink target, size and sha256, the raw inventory (records, QC-pool records, unique participants, replicates, plates, visit codes), participants × metabolites after every metabo_adni step, imputed points per table, a value summary of the cleaned table (zeros, share below 1, smallest positive, median), p180 participants per run, every output file's sha256, the predeclared counts beside the observed ones with every deviation listed, `findings`, and the pinned release's known upstream behaviours with their counts (below).
- **Predeclared counts** (the spike's), held in `CLEAN_EXPECTED_COUNTS` and checked by the manifest; a deviation is a finding, printed and recorded, never silent:

  | platform | read | after metabolite QC | after participant steps | imputed points | final |
  |---|---|---|---|---|---|
  | p180 | ADNI1 807 × 41 / 141, ADNI2GO 874 × 41 / 141 (UPLC / FIA) | ADNI1 28 / 110, ADNI2GO 31 / 121 metabolites | ADNI1 747 × 27 / 746 × 110, ADNI2GO 846 × 31 / 846 × 120 | 1651 | 1592 × 133; ADNI1 746, ADNI2GO 846; 0 duplicated participants |
  | nmr | 1646 × 250 | 245 metabolites | 1645 → 1563 (fasting) → 1504 (QC tags) | 155 | 1504 × 245; 41 zeros in 3 metabolites |

- **Known raw-file repair, by hash.** LONI's `ADMCDUKEP180UPLCADNI2GO.csv` lacks its closing quote (AGENTS.md); the archive copy carries the repair. `clean` records the sha256 of every input; the repaired hash (`7ad17d63…`) is named as such in the manifest; LONI's unrepaired hash (`f28ede9a…`) stops the step before metabo_adni runs, naming the repair the archive must carry (the step never edits the archive); an unknown hash for any input is a finding (a fresh LONI download), not an error.
- **The clean manifest is committed and synced.** `results/cleaned/` is ignored and excluded whole today, so the step would leave no committed trace. This change adds the single aggregate exception `results/cleaned/*/clean_manifest.json` to `.gitignore`, to `scripts/sync_results.sh` (filters and post-pull check) and to `constants.AGGREGATE_EXCEPTIONS`, in the same change, before the file exists. It holds hashes, options, versions and counts only. Every other file under `results/cleaned/` (the cleaned tables, `p180_runs.csv`, `logs/`) stays ignored and unsynced. No new participant-level path is introduced outside the already-ignored directory.
- **Upstream findings recorded, not patched** (constraint 3). In metabo_adni 0.5.8: (1) for a p180 metabolite whose missing values span several plates, every missing value receives the last plate's LOD/2 (34 metabolites, 1608 of the 1651 imputed points); (2) `ADNI2GO-UPLC` missing values receive the LOD itself, not LOD/2; (3) `read_meds_file` keeps `bl` rows where the medication table is nearly empty; (4) replicates are averaged per `RID` regardless of visit, and the NMR file holds 3 records at visits other than `bl`. The manifest records each with its count; the user reports (1)–(3) upstream and a later pin move re-issues `clean` by its own change.
- **`scripts/clean.sbatch`** for the cluster (partition `512x1024`, small resources, `ADNI_DATA_ROOT=/home1/tgonza/adni_sexdiff/data`, log under `results/cleaned/logs/`). It cannot run until the deploy key of constraint 7 and the cluster data copy exist (both the user's); the workstation run does not wait for it.
- **Docs**: `README.md` (the `clean` section: options, outputs, the working copy, the repair rule), `AGENTS.md` (status, step 1, constraint 1's ignore list, constraint 3's option list gains `--merge`, `CLEAN_OPTIONS` moves from undecided to decided with its value, the cluster script), `data.py` docstrings.

Out of scope, each its own change: the cohort (baseline visit, platform intersection, exclusions, `STAGE_RULE`, `ANALYSIS_COVARIATES`, whether the p180 run is a covariate); the export (`EXPORT_FEATURE_RULE`: which metabolites enter each block and on which scale, including the pseudo-count); any sensitivity arm (multivariate outliers, medication residuals, the paper's 0.4 participant cutoff); any fix to metabo_adni (reported upstream, pin moved by a change); the deploy key and the cluster data copy; later ADNI layers. No step here reads sex or stage.

## Capabilities

### New Capabilities
- `metabolomics-cleaning`: the `clean` step: metabo_adni's pipeline in a working copy with the decided options, the cleaned table per platform under metabo_adni's name, the p180 run provenance table, the captured log, the manifest with its predeclared-count check, and the version pin.
- `raw-input-integrity`: how a step treats the raw files of the data root: required names present, content resolved through the symlinks and hashed, known repairs recognised by hash, an unrepaired known-defective file refused, an unknown hash recorded. Written for `clean`; the cohort step reuses it for the clinical tables.
