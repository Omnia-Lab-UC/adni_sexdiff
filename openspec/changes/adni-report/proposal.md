# Proposal

## Why

Every step before `report` is implemented, run pinned on a data machine and committed: the primary analysis (`results/motco_analysis/`, change `adni-analyze`: CV-selected rank 8; `delta`, `angle` and `shape` not rejected at α = 0.05), its axis diagnostics (`results/motco_diagnostics/`), the predeclared `stage`-conditioned arm with its comparison and its own diagnostics (`results/motco_latent_sensitivity/`, change `adni-latent-sensitivity`, merged in PR #7: rank 4, every status `same`). The case study has no report: `run_report` is a stub whose docstring states the contract (`data.py`), and reading rule 8 promises that "report numbers are pasted from the generated files and checked by `report --check`". The template's reports (`../sead_sexdiff/reports/`) were written by hand with numbers pasted from the outputs, and nothing could check them; here the report is step 6 of the pipeline, so the check can be exact. This change implements step 6 and writes the first report. Every input it reads is a committed aggregate file, so the step and its check run on any clone, with no data root and no data machine.

## What Changes

- **`report` implemented** (`adni-sexdiff report`), the last step of the pipeline. It replaces the stub.
  - **Inputs**, the kept aggregate outputs only, and nothing else: the two `clean_manifest.json`; `results/cohort/stage_counts.csv` and `cohort_manifest.json`; the export's `manifest.json`; the primary's `result.json`, `analysis_manifest.json` and `summary.md`; the primary diagnostics' four CSVs, `diagnostics.md` and `diagnostics_manifest.json`; under `results/motco_latent_sensitivity/`, the arm's `result.json`, `analysis_manifest.json` and `summary.md` (`analysis/`), the comparison's three files (`comparison/`) and the arm diagnostics' six files (`diagnostics/`). It opens no participant-level file and needs none present: the hashes of `cohort.csv`, the export CSVs, `latent_scores.csv` and `analysis_metadata.csv` are read from the manifests, where the earlier steps recorded them after checking the files.
  - **Gates, before anything is written** (a failure stops the step naming the file or setting, both values and the step to rerun):
    - every input present;
    - every aggregate file hashes to the value its own manifest records;
    - the chain holds from `clean` to the arm's diagnostics: each manifest's recorded input hashes equal the manifests and files upstream (the clean manifests in the cohort and export manifests, the cohort manifest in the export manifest, the export manifest in the four analysis-reading manifests, the primary's two files as the arm's and the comparison's `reference`, the arm's two files in the comparison and in the arm diagnostics);
    - the runs are reported runs: the primary and the arm record `n_jobs = REPORTED_N_JOBS`, every manifest that carries a `numerics` block records `pinned` true, and every manifest that records a MOTCO, scikit-learn or metabo_adni version records the same one;
    - the primary is the primary (no latent adjustment, `is_primary` true in its diagnostics) and the arm is the predeclared arm (`LATENT_SENSITIVITY_ARM`, `is_primary` false in its diagnostics).
  - **The report**, `reports/motco-adni-<date>.md`, generated in full from the inputs; no sentence is typed by hand and every number is copied. In order: a summary; provenance (versions, revisions and `numerics` per manifest, every input with its sha256, the raw LONI inputs with their hashes and repairs as the clean and cohort manifests record them, the chain checks); the cohort (the rules as applied, the cascades, the sex × stage tables of both platform sets and the intersection, the intersection's `DX.bl` × phase cells, the per-cell covariate descriptives, the cleaning counts and options); the export (the feature rule as applied, features per block and status, block shares, the run offset per block); the primary analysis (settings by constant name, MOTCO's defaults read back, the statistics with p-values, rejection and null summaries, the cell sizes, the latent space with the rank, floor and eigengap beside `angle`, the covariate block and reference row, the `cli_equivalent`); the primary's axis diagnostics (flagged rows, the components table, the block PCs against phase beside the export's value); the latent-adjustment sensitivity (the comparison with a status per statistic, the latent spaces, the arm's `latent_adjustment` block, the covariate roles, MOTCO's two decisions, the arm's diagnostics beside the primary's, the arm's `cli_equivalent`); the findings of every manifest, copied; `READING_RULES` then `LATENT_SENSITIVITY_READING_RULES`, verbatim; the commands that reproduce the pipeline and check the report.
  - **Interpretation only by rule.** The report's reading sentences are the ones `summary.md` and `latent_sensitivity.md` already generate from the rejection statuses (a non-rejection uninformative, a `delta` rejection a difference and not of size, an arm status `same` or `differs (basis dependence)`, the arm's non-rejection weaker), produced by the same code so that the three documents are string-equal. The report adds no other interpretive sentence. The primary's status is the result in every table; the arm is read beside it.
  - **Deterministic body.** The report body depends on the inputs and the report's file name only: the date lives in the file name and the title, and no report-time revision, host, time or runtime is written. Two runs on the same inputs are byte-identical.
  - **`--check`**: reads the report at `--out` (default: the newest `reports/motco-adni-*.md`), runs the same gates, regenerates the report from the inputs now on disk with the date taken from the file name, and compares: every table cell by cell, every other line line by line. Every mismatch is named (section, table, row, column, the report's value and the generated one; or the line) and the step exits non-zero. Nothing is written. A report whose inputs were regenerated since it was written fails the check on the provenance hashes, which is the intended discipline: the committed report corresponds to the committed outputs.
  - **Output discipline.** The report is written to a temporary file and renamed when complete; an existing report at `--out` stops the step unless `--force`. After writing, the step parses the file back through the checker's parser and verifies the parsed tables equal the generated ones, so a parser defect surfaces at write time. The report quotes aggregate values only and holds no participant identifier; `reports/` is committed and unchanged in `.gitignore`, the sync filter and `PARTICIPANT_LEVEL_PATTERNS`.
  - **Findings, never stops**, printed in the report's findings section: every deviation and finding of every input manifest, copied verbatim and attributed to its step; a manifest whose recorded revision is dirty; a manifest without a `numerics` block (written before `adni-portable-numerics`).
- **Flags**: `--cleaned-dir`, `--cohort-dir`, `--input-dir`, `--analysis-dir`, `--diagnostics-dir`, `--sensitivity-dir` (the root of `results/motco_latent_sensitivity/`, read as `analysis/`, `comparison/` and `diagnostics/`), `--out`, `--check`, `--force`. Every default is the pipeline's directory. No flag selects what is reported.
- **Constants**: conventions only. `REPORT_NAME` exists; this change adds `REPORT_INPUT_FILES` (every file the step reads, by directory) and `REPORT_SECTIONS` (the section titles, in order).
- **Shared sentences.** The per-statistic reading lines of `render_analysis_summary` and the status lines of `render_latent_sensitivity` move into helpers the report calls. The committed `summary.md` of the primary and of the arm, and `latent_sensitivity.md`, re-rendered from the committed records, must keep the bytes their manifests record; that gate runs on any clone.
- **Docs**: `README.md` (the status, a `report` section with the command, flags, gates, sections, the check and the commit discipline, the quick start) and `AGENTS.md` (the status, step 6, the Layout entries, the "Flag and ask" paragraph unchanged since no constant is added), the `constants.py` docstring, the `run_report` docstring.
- **The first report**, written on the clean tree at the implementing commit from the committed outputs, checked with `--check`, and committed.

Scientific constants introduced by this change: none. The report decides nothing: it quotes `READING_RULES`, `LATENT_SENSITIVITY_READING_RULES` and every setting by constant name from the manifests, and every number from the records.

Out of scope, each its own change:
- A written discussion of the results. The report is the generated record; a manuscript or note that interprets it quotes the report and is not checked by this step.
- Figures, HTML or PDF rendering.
- The export sensitivity variants, the CN / LMCI / AD arm and the rank sweep. Each later variant or arm extends the report's sections by its own proposal.
- A MOTCO pin move and its re-issue report (the template's `motco-release-migration`).
- The cluster run of the earlier steps (constraint 7). The report itself needs no cluster: it reads committed files.
- Any change to the outputs of `clean`, `cohort`, `export`, `analyze`, `axis-diagnostics` or `latent-sensitivity`.

## Capabilities

### New Capabilities
- `case-study-report`: the `report` step. It covers the inputs (kept aggregate outputs only, no participant-level file), the gates (hashes, the chain, reported runs, the primary's and the arm's identity), the report's content contract, the rule that every number is pasted and every interpretive sentence is generated by rule, the reading rules carried verbatim, the deterministic body, `--check` with cell-level mismatches, the output discipline and the no-identifier rule.

### Modified Capabilities
- None. `motco-trajectory-analysis` ("Reading rules bind every reader of the result") and `motco-latent-adjustment-sensitivity` ("Reading rules bind every reader of the arm") already bind "every report"; this change fulfils them without changing their text. `latent-axis-diagnostic` is unchanged.

## Impact

- `src/adni_sexdiff/constants.py`: the conventions `REPORT_INPUT_FILES` and `REPORT_SECTIONS`; the docstring names the change. No scientific constant.
- `src/adni_sexdiff/data.py`: `run_report` (the gates, the loader, write and check modes), `render_report` and the table builders, the report parser and `check_report`, the chain check of the full pipeline; the reading-line helpers shared with `render_analysis_summary` and `render_latent_sensitivity` (their bytes unchanged).
- `src/adni_sexdiff/cli.py`: the `report` subcommand's nine flags and its `[report]` progress lines (counts and file names only).
- `reports/motco-adni-<date>.md`: committed. It is aggregate: every value in it is copied from a committed aggregate file or a constant.
- `.gitignore`, `scripts/sync_results.sh`, `PARTICIPANT_LEVEL_PATTERNS`: unchanged; no participant-level output is added.
- Dependencies: none new. The Markdown tables are written and parsed by the package itself; pandas reads the CSVs.
- Compute: seconds; no MOTCO call, no numeric computation beyond formatting, so the step needs no pinned numerics and records none.
- Machines: any machine with the Nix shell and the committed tree. The inputs are the tracked files under `results/`; no data root and no data machine is needed to implement, verify or run the step, and a clone without the participant-level files runs it unchanged.
- Workflow: a report is committed only after `report --check` passes on the clean tree; regenerating any results directory invalidates the committed report until it is rewritten and checked again.
