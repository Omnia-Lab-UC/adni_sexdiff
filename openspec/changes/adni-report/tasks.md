# Tasks

This change introduces no scientific constant. Before the apply starts, the user accepts the proposal's two decisions: the report is generated in full with no hand-written text (design D1), and its body depends on the inputs and the file name only, with the provenance section as its manifest (design D2).

Every task runs on any machine with the Nix shell and the committed tree: the inputs are the tracked files under `results/`, no data root, data machine or participant-level file is needed, and the step records no numerics. Scratch copies and scratch outputs live in the session scratchpad, never under `results/` or `reports/`, except task 6.1. No task line records a participant value.

## Workflow follow-up

- Archive the change after the report is committed and the PR is merged. The archive creates `openspec/specs/case-study-report/`.
- A regenerated results directory invalidates the committed report: `report --check` fails on its provenance cells until a new report is written and checked. Each later variant or arm extends the report's sections by its own proposal and re-issues the report.
- Next changes, each its own proposal: the export sensitivity variants, the CN / LMCI / AD arm, the rank sweep; the cluster run of the earlier steps once the deploy key exists (constraint 7), after which the pulled manifests must reproduce the committed hashes and the report's check still passes.
