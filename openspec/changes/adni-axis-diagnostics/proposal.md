# Proposal

## Why

The primary analysis exists (`results/motco_analysis/`, change `adni-analyze`, committed at `af4d6e4`: CV-selected rank 8, `delta`, `angle` and `shape` not rejected at α = 0.05, no deviation, no finding), and that change decided three things that make this step the next one: a latent component that tracks the p180 run is a reading matter for `axis-diagnostics`, not an adjustment of the primary (reading rule 6); the `stage`-conditioned latent arm (`ANALYSIS_PREDECLARED_LATENT_SENSITIVITY`) runs only after this diagnostic has measured the primary's components against phase; and the report (step 6) carries the diagnostics' flagged rows. The kept aggregate files already say the question is live: the export recorded that the p180 block's first principal component correlates 0.73 with phase (median |d| 1.12 over its 133 metabolites, NMR 0.13 and 0.21), and the record's covariate block gives `phase[ADNI2GO]` a coefficient of 8.0 on `pls_0`, several times the spread of the stage means along that component (`statin[1]` 4.1; the others below 1.5). Nothing in the repository measures, from the kept files, what each latent component and each block axis correlates with, how much of the sex × stage geometry lies along each component, or which block carries each component. `axis-diagnostics` is a stub and its two constants are undecided. This change decides them and implements step 5 as AGENTS.md binds. No number in this proposal comes from a diagnostic run on ADNI data; every value quoted is from a committed manifest or record.

## What Changes

- **The diagnostic constants decided**, each a named constant in `constants.py` (decided by the user on 2026-10-27, before any run; the two additions to the stub's contract below, `components.csv` and the conditioning on the record's six design columns, were decided with them):
  - `DIAGNOSTIC_VARIABLES`: eight participant-level variables, each with its source among the kept outputs and its derivation, never chosen or extended from a result:
    - from `covariates.csv` (export), as the analysis codes them: `age` (years), `education` (years), `apoe4` (ε4 allele count 0 / 1 / 2, read as ordinal), `phase` (1 for `ADNI2GO`, 0 for `ADNI1`: the p180 run, the design column `phase[ADNI2GO]`), `statin` (1 / 0);
    - from `metadata.csv` (export), the design: `stage` (ordinal CN 0, MCI 1, AD 2) and `male` (1 for Male, 0 for Female);
    - from `cohort.csv` (cohort), the enrollment category the stage rule merged: `dx_bl` (ordinal CN 0, SMC 1, EMCI 2, LMCI 3, AD 4, ADNI's enrollment gradient). It is read so the tables show whether a component separates SMC from CN or EMCI from LMCI, which `STAGE_RULE` does not, and because SMC and EMCI exist only in ADNI-GO/2: a phase axis is also a `dx_bl` axis, and the partial correlation has to show which it is.
    - Considered and not included: `protocol` (ADNI1 / ADNIGO / ADNI2; it differs from `phase` only by splitting GO from 2, which is no assay run), `visit` (constant `bl`), and any raw-data variable (BMI, fasting state, plate): the diagnostic reads kept outputs only, and the plate is metabo_adni's cross-plate correction, not an exported quantity.
  - `DIAGNOSTIC_CORRELATION_THRESHOLD = 0.3`: a reporting flag on |Spearman ρ|, raw and partial, for latent components and block PCs alike; the template's value. It reads magnitude, not significance: at n = 1501 the sampling SD of ρ under independence is about 0.026, so a flag lies far outside sampling noise, and no p-value is attached to any correlation. It is not an adoption rule: nothing is chosen from a flagged row.
  - Conventions, not scientific choices: the partial correlation conditions on the six design columns of the record (`age`, `education`, `apoe4[1]`, `apoe4[2]`, `phase[ADNI2GO]`, `statin[1]`, built from `covariates.csv` with the codings the export manifest records and checked against the record's `design_columns`), exactly the covariate design of the stage-means model, so a partial reads as what the model's adjustment leaves; `DIAGNOSTIC_N_BLOCK_PCS = 3` (the export recorded PC1 and PC2 against phase; three keeps the next one); the output names (`DIAGNOSTICS_*`: the five names reserved in `constants.py` plus `components.csv`).
- **`axis-diagnostics` implemented** (step 5). It reads `results/motco_input/` (the two blocks, `metadata.csv`, `covariates.csv`, each checked against the sha256 in `manifest.json`), `results/motco_analysis/` (`result.json`, `latent_scores.csv`, `stage_means.csv`, `pls_loadings.csv`, `analysis_manifest.json`; the analysis manifest's recorded input hashes checked against the export files now on disk, the chain) and `results/cohort/` (`cohort.csv` checked against `cohort_manifest.json`, whose own hash must equal the one the export manifest records; the rows with both platform flags must be the exported participants in export order), and nothing else. A mismatch stops it before anything is written, naming the file and the step to rerun. It writes `results/motco_diagnostics/` (staged as `motco_diagnostics.tmp/`, renamed when complete; an existing directory stops it unless `--force`):
  - `axis_correlations.csv`: per latent component × variable, the Spearman ρ, the partial Spearman ρ given the six design columns (the Spearman correlation of the OLS residuals of both on an intercept and the six columns; n/a for a variable in the conditioning set), the pairwise-complete n, the component's score SD and a flag per correlation;
  - `block_pcs.csv`: the same for the first three principal components of each z-scored block (`p180.csv`, `nmr.csv`: population SD, SVD, each sign fixed by its largest loading), with the component's variance share;
  - `geometry_shares.csv`: from `stage_means.csv`, per component the share of the squared length of each sex's net displacement (AD minus CN, what `angle` reads), of the per-stage sex-difference vectors and of the stage-centred sex differences;
  - `components.csv`: per latent component, the score SD, the share of its squared `pls_loadings.csv` entries (MOTCO's rotation weights on z-scored features) held by each block (p180 and NMR enter unweighted, 133 / 298 and 165 / 298 features), the number of flagged variables and the variable with the largest |ρ|;
  - `diagnostics.md`: what the tables are and are not, the flagged rows first (latent components, then block PCs), the component summary, the full variable × component table, the block PCs beside the export's recorded phase offset (`|corr(PC1, phase)|` 0.73 p180 and 0.13 NMR, Pearson), the geometry shares, the findings and `READING_RULES` verbatim;
  - `diagnostics_manifest.json`: versions, git revision, every input with its sha256 and the chain checks, the analysis read (its manifest's hash, `latent_adjustment`, `n_jobs`, selected rank, whether it is the primary), the variables with sources and derivations, the threshold, the conditioning columns, the definition of every statistic, counts (participants, components, variables, rows and flags per table, PC variance shares, the Spearman of each block's PC1 with `phase` beside the export's Pearson value), the predeclared `DIAGNOSTICS_EXPECTED_COUNTS` beside the observed ones with deviations, output hashes (every one aggregate), findings.
  Every file is per component, per block or per variable: nothing participant-level is written, no `rid` appears, and all six files are committed. `.gitignore`, `scripts/sync_results.sh` and `PARTICIPANT_LEVEL_PATTERNS` need no change (constraint 1 already names the diagnostics tables as aggregate).
- **Predeclared counts** (`DIAGNOSTICS_EXPECTED_COUNTS`, from the committed export, cohort and analysis manifests, none from a diagnostic run): participants 1501 with the sex × stage cells (Female CN / MCI / AD 237 / 310 / 125, Male 223 / 448 / 158); 8 variables under the names above; 6 conditioning columns under the record's names; 2 blocks with 133 and 165 features and 3 PCs each; for the primary analysis, rank 8 (`latent.selected_lv` of the committed `result.json`) and `component_selection` `cv`, so the tables hold 64 axis rows, 48 block-PC rows, 32 geometry rows and 8 component rows. A deviation is a finding, printed and recorded, never silent and never a stop. Findings also record: an analysis read whose `n_jobs` is not 1 (its draws are not the reported ones; the scores are unaffected) or that is not the primary (`latent_adjustment` not null, or a non-default `--analysis-dir`, so the primary's rank is not expected); a variable that is constant or has fewer than three complete rows (ρ undefined); and, per component, the flagged variables as counts and names.
- **Runs on an arm.** `--analysis-dir` and `--out-dir` let the next change (`adni-latent-sensitivity`) run the same diagnostic on its `stage`-conditioned arm, whose directory mirrors the primary's; the manifest records which analysis was read and that it is not the primary. No other flag; no setting is a flag.
- **Docs**: `README.md` (status; an `axis-diagnostics` section: the command and flags, the inputs and the chain checks, the variables with their sources, the statistics with their definitions, the threshold, the outputs, the no-downstream-read rule, the reading rules); `AGENTS.md` (status; step 5 as built; "Flag and ask" with both constants decided and their values; the Layout entries; the "Data & domain notes" paragraph on the run offset, which already names this step); the `constants.py` docstring (no undecided name remains) and the `run_axis_diagnostics` docstring.

Precedent and departures. The template's `mtg-astrocyte-technical-axis-diagnostic` change read several analyses (the primary and a forced-rank sweep), a per-donor technical table built from the raw nuclei and the export's feature-selection accounting, and wrote its report in the same change. Here there is one analysis (an arm is read by flag, later); the only technical variable the kept outputs hold is the run (`phase`); the export selects features by family, not by abundance or variance, so there is no selection accounting, and the block composition of each component (`components.csv`) takes its place because the two blocks enter unweighted and one of them carries the run; the partial correlations condition on the record's six categorical-coded design columns rather than on six numeric covariates; `dx_bl` is added as the merged sub-stage ordinal; and the report stays step 6. The threshold and the definition of every statistic are the template's.

Out of scope, each its own change:
- The `stage`-conditioned latent arm (`adni-latent-sensitivity`, next; it reads this step's primary diagnostic and reruns the diagnostic on its arm) and `report` (step 6, which pastes the flagged rows).
- Per-sex or per-stage stratified correlations, a p-value or interval on any correlation, a rank sweep, an adoption rule of any kind, a per-metabolite correlation table (the report's or a later change's reading of `pls_loadings.csv`), MOTCO's attribution.
- Any change to `clean`, `cohort`, `export` or `analyze`; a MOTCO pin move; the cluster run (the diagnostic takes seconds on a workstation and reads no raw file; it runs wherever the analysis outputs are).

No value in these tables changes a constant, selects a variant or reruns the primary: the diagnostic reads sex and stage, so it is never a filter, and no `export` or `analyze` run reads `results/motco_diagnostics/`.

## Impact

- `src/adni_sexdiff/constants.py`: scientific, decided here: `DIAGNOSTIC_VARIABLES`, `DIAGNOSTIC_CORRELATION_THRESHOLD`; predeclared: `DIAGNOSTICS_EXPECTED_COUNTS`; conventions: `DIAGNOSTIC_N_BLOCK_PCS`, `DIAGNOSTIC_CONDITIONING_COLUMNS` (the six design-column names, derived from `ANALYSIS_EXPECTED_COUNTS["design_columns"]`), `DIAGNOSTICS_COMPONENTS` (`components.csv`), `DIAGNOSTICS_ANALYSIS_FILES`, `DIAGNOSTICS_GEOMETRY_QUANTITIES`; the docstring's undecided list becomes empty.
- `src/adni_sexdiff/data.py`: `run_axis_diagnostics` replacing the stub; the statistics (`spearman`, `partial_spearman`, `block_principal_components`, `geometry_shares`, `block_loading_shares`), the input and chain checks (the export loader of `analyze` reused with the step name as a parameter, the cohort check of `export` reused), the renderer `render_axis_diagnostics`; the manifest and `.tmp` helpers reused. `cli.py`: no new flag (`--input-dir`, `--analysis-dir`, `--cohort-dir`, `--out-dir`, `--force` exist); progress messages with counts only.
- Ignore rules, sync filter, `PARTICIPANT_LEVEL_PATTERNS`: unchanged (every output is aggregate).
- Dependencies: none new (scipy's `spearmanr`, numpy's `lstsq` and `svd`; scipy is in the lock through MOTCO).
- Compute: seconds on the workstation (one 1501 × 133 and one 1501 × 165 SVD, 64 partial regressions). No cluster time.
- `results/motco_diagnostics/` on the workstation (new); its six files are committed, named one by one with why each is aggregate.
- Scientific choices introduced here (flag and ask before changing): `DIAGNOSTIC_VARIABLES` (the eight variables, their codings, `dx_bl`'s ordinal), `DIAGNOSTIC_CORRELATION_THRESHOLD` (0.3), and the rule that the diagnostic never feeds a filter or a variant.
